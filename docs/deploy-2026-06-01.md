# 배포 가이드 — 서버에 올려 테스트하기 (2026-06-01)

현재 쇼핑몰은 **단일 정적 HTML**(`shop/index.html`, 데이터는 브라우저 localStorage)입니다.
따라서 "서버 배포 = 정적 호스팅"이며, 별도 백엔드 없이 바로 공개 URL에서 테스트할 수 있습니다.

> ⚠️ 기존 `shop/lightfactory-netlify.tar.gz`는 항상 **현재 `shop/index.html` 기준으로 재생성**해야 합니다(옛 버전 배포 함정 방지). 아래 3·B 방식은 자동으로 최신본을 올립니다.

---

## 가장 빠른 3가지 방법

### A. Netlify Drop (계정 설정 최소, 드래그앤드롭) — 추천(첫 테스트)
1. `shop/lightfactory-netlify.tar.gz` 압축 해제 (안에 `index.html` + `_redirects`)
2. https://app.netlify.com/drop 에 **압축 푼 폴더**를 드래그
3. 즉시 `https://<랜덤>.netlify.app` URL 발급 → 그 URL로 테스트
   - 이 패키지는 이미 최신 코드로 재생성돼 있음(584KB).

### B. Netlify / Vercel — Git 연결(자동 배포, 권장 상시 운영)
저장소를 GitHub에 올린 뒤 Netlify 또는 Vercel에 연결하면, 설정 파일이 이미 있어 **추가 설정 없이** 빌드됩니다.
- `netlify.toml` / `vercel.json` 가 `shop/index.html` → `dist/`로 복사해 배포 → 항상 최신.
- CLI로도 가능:
  ```bash
  # Netlify
  npx netlify deploy --prod
  # Vercel
  npx vercel --prod
  ```

### C. GitHub Pages 자동배포 (이 저장소에 세팅 완료) ⭐
`.github/workflows/deploy.yml` 가 이미 커밋돼 있어, **main/master에 push되면 자동으로 Pages 빌드·배포**됩니다.
최초 1회만 GitHub 인증 + 레포 생성이 필요합니다(아래).

**방법 1 — gh CLI (가장 간단, 레포 생성+푸시 한 번에)**
```bash
# 1) gh 설치 (Windows)
winget install GitHub.CLI
# 2) 로그인 (브라우저 열림) — 터미널에서 직접 실행
gh auth login
# 3) public 레포 생성 + 원격 연결 + 푸시 (저장소 폴더에서)
gh repo create lightfactory-cowork --public --source=. --remote=origin --push
# 4) Pages 소스를 Actions로 (자동 안 되면 1회)
gh api -X POST repos/{owner}/lightfactory-cowork/pages -f build_type=workflow 2>/dev/null || true
```

**방법 2 — gh 없이 (github.com에서 빈 레포 생성 후)**
```bash
git remote add origin https://github.com/<사용자명>/lightfactory-cowork.git
git push -u origin master          # 인증 프롬프트(브라우저/PAT)
# 그 후 GitHub → Settings → Pages → Source = "GitHub Actions" 선택
```

- 배포 URL: `https://<사용자명>.github.io/lightfactory-cowork/`
- push 후 GitHub의 **Actions 탭**에서 배포 진행상황 확인. 완료되면 위 URL 접속.
- ⚠️ **Public 레포라 관리자 기본 비번 해시(12345678)가 노출**됩니다. 배포 직후 콘솔에서
  `await changeAdminPassword('새비번')` 으로 변경하세요.

## 🔑 서버(비-localhost) 환경에서 달라지는 점 — 테스트 전 필독

1. **HTTPS 필수**: 비밀번호 해시(`crypto.subtle`)는 보안 컨텍스트에서만 동작. Netlify/Vercel은 기본 HTTPS라 OK. (http로 띄우면 로그인 실패)

2. **dev 패널의 역할 전환 제한** (보안 가드):
   - localhost에서는 dev 패널로 guest/consumer/pending/T1/T2/T3 모두 전환 가능.
   - **서버(비-localhost)에서는 admin·T1·T2·T3 강제 전환이 차단**됩니다(의도된 보안).
   - 따라서 서버에서 **도매(T1~T3) 화면을 테스트하려면**: 사업자 회원가입 → 관리자 승인 → 그 계정으로 로그인. (같은 브라우저에서 순서대로 진행 가능)

3. **관리자 로그인**: 로고 더블클릭 → `junil98@gmail.com` / `12345678`
   - ⚠️ 공개 URL에 올리기 전 비밀번호 변경 권장: 콘솔에서 `await changeAdminPassword('새비번')`

4. **데이터는 브라우저별 localStorage**: 기기/브라우저마다 별개, 새로고침엔 유지되나 캐시 삭제 시 초기화. 다중 사용자 공유·동기화는 백엔드 이관 후 가능.

5. **결제**: 토스 키 미설정 시 시뮬레이션 모드. 실제 결제·금액검증은 백엔드(`lightfactory-v2`) 이관 필요(데모 단계에서는 올리지 말 것).

# 역할별 테스트 계정 세팅 (2026-06-11)

대상: `shop/index.html` · Public 데모/QA 편의를 위한 역할별 로그인 계정 정비

## 계정 (아이디 = 비밀번호)
| 역할 | 아이디 | 비번 | 로그인 경로 |
|---|---|---|---|
| 관리자 | `1` | `1` | 로고 더블클릭 → 관리자 로그인 |
| 사업자 T3 | `2` | `2` | 일반 로그인 |
| 사업자 T2 | `3` | `3` | 일반 로그인 |
| 사업자 T1 | `4` | `4` | 일반 로그인 |
| 일반소비자 | `5` | `5` | 일반 로그인 |

## 변경 내역
- `ADMIN_CREDENTIALS`: 관리자 id `1` / pw `1` (SHA-256(pw+salt) 해시 저장, salt `lf_admin_salt_v1`).
- `SEED_USERS` 신설 + `USERS` 초기값을 시드 깊은복사로 구성. 사업자 3계정은 **승인완료(tier T1~T3)** 상태로 시드 → 로그인 즉시 도매가·세금계산서 테스트 가능(가입·승인 절차 불필요). 각 계정에 `bizInfo`(상호·사업자번호·업태·종목) 포함.
- `loadAllFromStorage`: `lf_users` 가 시드를 덮어쓰는 문제 → **시드 병합 로직** 추가(저장본에 시드 이메일이 없으면 추가). 기존 방문자도 테스트 계정 확보.
- 로그인창 데모 헬퍼: 역할별 자동입력 버튼으로 교체 + `fillDemoLogin()` 추가. 노출 조건을 localhost **또는 `*.github.io`** 로 확장(운영 도메인에서는 숨김).

## 검증 (Playwright + 시스템 Chrome)
- 5/5·4/4·3/3·2/2 일반 로그인 → role consumer/t1/t2/t3 정확 매핑 ✅
- 1/1 관리자 자격증명 해시 일치 ✅

## ⚠️ 보안 주의
- 자격증명 `1`~`5` 는 **Public 데모/테스트 전용**. 데이터는 브라우저 localStorage(공용 DB 아님), 결제는 토스 키 없을 시 시뮬레이션 → 실제 피해 범위 없음.
- **실서비스 전 반드시 교체**: 관리자는 `await changeAdminPassword('강력한새비번')`, 시드 계정/데모 헬퍼 블록 제거 권장.
